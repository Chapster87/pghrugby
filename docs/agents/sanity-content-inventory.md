# Sanity Content Inventory and Rehoming Map

Research asset for [Research: Sanity content inventory and rehoming map](https://github.com/Chapster87/pghrugby/issues/4) (wayfinder map ticket).

Scope: every Sanity document type in `pghrugby/nextjs`, who consumes it at runtime, its target home (DatoCMS or ForgeCMS), and a replace → verify → delete removal sequence that keeps the site working at every step.

As of this research, the app is already in a mixed state: homepage/pages/membership render from DatoCMS, standings/links/contact/teams render from ForgeCMS, and everything else still reads from Sanity. This map documents the remainder.

## Document types

## Runtime consumers (file → types → queries)

### Site chrome

- `src/components/header/index.tsx` — `settings` (`*[_type == "settings"] … title`), `navigation` (`navQuery` → `mainNav`, submenus)
- `src/components/header-checkout/index.tsx` — `settings` (title only)
- `src/components/footer/index.tsx` — `navigation` (`footerNavQuery` → `footerNav`), `socialMedia` (`footerSocialsQuery`)
- `src/components/sponsor-bar/index.tsx` + `sponsor.query.ts` — `sponsorBar` (`sponsorQuery` → `items[].sponsor->`)

### Editorial

- `src/app/(core)/post/[slug]/page.tsx` + `posts.query.ts` — `post` (`postQuery`, `postPagesSlugs`); derefs `author->`, `categories[]->`, `tags[]->`, embedded `seo`
- `src/components/sidebar/index.tsx` + `_data/content.query.ts` — `post` (`latestContentQuery`, latest 5)
- `src/app/(core)/sitemap/page.tsx` — `post` slugs + `page` slugs (human sitemap; the XML sitemap is generated statically by `next-sitemap.js`)

### Competition

- `src/app/(core)/matches/all/page.tsx` + `schedule.query.ts` — `match` (`scheduleQuery`) + per-match derefs of `team` and `season`; teams already come from ForgeCMS (`teamsQuery`) — this page is the only Sanity/ForgeCMS hybrid
- `src/components/competition/scheduleTable/index.tsx` + `schedule.query.ts` — `match` (parameterized by league/division/season) + `team`, `season` derefs
- `src/components/competition/countdown/index.tsx` + `match.query.ts` — `match` (next upcoming) + league/division/season/team derefs
- `src/components/sidebar/_components/matches/*` — `match` (`matchQuery`, next upcoming) + derefs

### Product content

- `src/app/(core)/product/[handle]/page.tsx` + `product.content.query.ts` — `product` (`productContentQuery` keyed by handle: title, description, specs, addons, `form->`, embedded `seo`)
- `src/modules/products/components/product-form/index.tsx` — `product` (`form->{_id, title, formFields}` deref) → `formType`

### Sanity infrastructure (removed in teardown, not "content")

- `src/app/(core)/layout.tsx` — `<SanityLive />`, `<VisualEditing />`, draft-mode wrapper
- `src/app/api/draft-mode/enable/route.ts` — `defineEnableDraftMode` (needs `SANITY_VIEWER_TOKEN`)
- `src/app/studio/[[...tool]]/page.tsx` — mounts Sanity Studio
- `sanity.config.ts`, `sanity.cli.ts`, `src/sanity/**` (env, two client instances, lib/live, lib/image, lib/utils, schemas, fragments, components, structure.config)
- `src/components/PortableText.tsx` — Sanity portable-text renderer; used only by the post page
- `src/components/PageBuilder.tsx` — dead renderer for Sanity `pageBuilder` blocks; **no imports** (leftover from the homepage/pages move)
- `src/app/(core)/(home)/video-bg/index.tsx` — hardcoded `cdn.sanity.io` video URLs
- `migrations/import-wp/` — WordPress → Sanity import (posts, pages, categories, tags, users)

Note: two Sanity clients exist with different configs — `src/sanity/lib/client.ts` (used by chrome + competition components) and `src/sanity/client.ts` (used by sidebar, product-form, draft-mode; carries `stega` + `SANITY_VIEWER_TOKEN`).

## Rehoming map

| Target                                 | Document types                                                               | Gate / status                                                                                                |
| -------------------------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| **ForgeCMS** (site chrome)             | `navigation`, `settings`, `socialMedia`, `sponsor`, `sponsorBar`, `linktree` | Gated on ForgeCMS capability gate (#5) — chrome models via `cms-starter`; DatoCMS is the documented fallback |
| **ForgeCMS** (competition)             | `match`, `team`, `season`, `league`, `division`, `standings`                 | ForgeCMS already serves standings and teams; matches/schedules are the open gap (#8)                         |
| **DatoCMS** (editorial)                | `post`, `page`, `author`, `category`, `tag`, `seo`                           | Pages already live on DatoCMS; posts migration is ticket #14                                                 |
| **DatoCMS** (product content, interim) | `product`, `formType`                                                        | Modeling prototype is ticket #12                                                                             |
| **Delete, no rehome**                  | `homepage`, `membership`                                                     | Already replaced by DatoCMS — types are dead                                                                 |
| **Studio-only**                        | `media.tag`, all object types                                                | Removed with the schema folder                                                                               |

## Removal sequence

Rules: replace → verify → delete, site keeps working at every step. Each phase is independent, so phases 1–4 can proceed in parallel (or any order); phase 5 is the common tail. "Verify" = `pnpm build` + `pnpm lint` + manual check of the listed routes (plus draft-mode check for editorial).

### Phase 1 — Competition → ForgeCMS (blocked on gate #5; fallback DatoCMS)

1. **matches/all**: replace Sanity `scheduleQuery` + per-match `team`/`season` derefs with ForgeCMS GraphQL (teams already ForgeCMS). Verify `/matches/all`.
2. **scheduleTable**: replace Sanity query with ForgeCMS schedules. Verify `/mens-schedule`, `/womens-schedule`.
3. **countdown + sidebar matches**: replace `matchQuery` with a ForgeCMS next-match query. Verify countdown on `/matches/all` and the sidebar widget.
4. **Delete** the Sanity competition types and their query files (`match`, `team`, `season`, `league`, `division`, `standings`). Standings needs no replacement — delete the type once ForgeCMS standings are confirmed.

### Phase 2 — Editorial → DatoCMS (ticket #14)

5. **Posts**: extend the WordPress→DatoCMS scripts; replace `postQuery`/`postPagesSlugs`, sidebar `latestContentQuery`, and the sitemap blog-post query with DatoCMS. Verify `/post/[slug]`, sidebar, `/sitemap`. Requires draft/preview parity (map fog).
6. **Pages**: repoint sitemap `getAllSanityPages` to DatoCMS `allPages` (the `/[slug]` route is already DatoCMS). Verify `/sitemap`.
7. **Delete** `post`, `author`, `category`, `tag`, `page`, and the `seo` fragment.

### Phase 3 — Product content → DatoCMS interim (modeling via #12)

8. Replace `productContentQuery` (product/[handle] metadata + `ProductName`) and the product-form `form` deref with DatoCMS models. Verify `/product/[handle]` and the product form.
9. **Delete** `product`, `formType`.

### Phase 4 — Site chrome → ForgeCMS (gated on #5; DatoCMS fallback)

10. Replace header `navQuery` + `settingsQuery`, header-checkout `settingsQuery`, footer `footerNavQuery` + `footerSocialsQuery`, sponsor-bar `sponsorQuery`. Verify every page (header/footer are global).
11. **Delete** `navigation`, `settings`, `socialMedia`, `sponsor`, `sponsorBar`, `linktree`.

### Phase 5 — Sanity teardown (new ticket, blocked by phases 1–4)

12. Remove `<SanityLive />`/`<VisualEditing />` from `(core)/layout.tsx` and the draft-mode route; remove the studio route; delete `src/sanity/**` and the two client modules; delete `PortableText`/`PageBuilder` if unused; drop Sanity deps (`sanity`, `next-sanity`, `@sanity/*`, `sanity-plugin-*`, `@portabletext/react`) from `package.json`; clear `NEXT_PUBLIC_SANITY_*` / `SANITY_VIEWER_TOKEN` / `SANITY_STUDIO_*` env vars; rehost the `video-bg` assets off `cdn.sanity.io`.
13. Archive `migrations/import-wp/` (per standing preference, migration files stay until WordPress content is confirmed landed — ticket #9), then delete.

## Notes and risks

- **Hardcoded season parameters**: schedule pages, countdown, and the sidebar widget all hardcode `seasonYear={2025}`, `seasonName="Fall"`, league/division names. The ForgeCMS replacement must decide how seasons/leagues/divisions are selected (or make them configurable).
- **Sitemap is two things**: the human `/sitemap` page (which still queries Sanity posts + pages) and the static XML sitemap from `next-sitemap.js` (no CMS dependency).
- **`seo` is a document type used as an inline object** — no standalone `seo` documents are queried; it rides along with its parent type.
- **Dead code to remember**: `PageBuilder.tsx` (no imports), the Sanity `homepage`/`membership`/`standings`/`linktree` types (no runtime consumers).
- **Two Sanity client modules** with different configs must both be removed in teardown.
- **`matches/all` is the only hybrid page** — worth treating as the pilot for competition migration since half of it (teams) is already ForgeCMS.
